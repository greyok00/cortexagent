# CortexAgent — Full Audit Report (2026-08-11)

> Consolidated findings from a 5-agent parallel audit of `/home/cortexagent`
> (core lifecycle, proxy/model, UI/session, peripheral, memory/CLI/install) plus
> the smoke-test gate. Severity: 🔴 CRITICAL · 🟠 HIGH · 🟡 MEDIUM · ⚪ LOW.

---

## 🔴 CRITICAL

### C1. `lib/session_bridge.py:52` — `write()` replaces the whole session file with one line
```python
with os.fdopen(fd, "w", encoding="utf-8") as f:
    f.write(line)                 # only the new line goes into tmp
os.replace(tmp, str(self._path))  # tmp REPLACES the whole file
```
Every `write()` clobbers all prior events. The docstring claims "append-only
JSONL" and "atomic append", but `os.replace` is atomic *replace*, not append.
The plain-append fallback (lines 54–59) is only reached if `mkstemp`/`write`/
`replace` raises — effectively dead code. **Impact:** `read_new()` and the webui
SSE reader only ever see the *last* event; every prior message is destroyed. The
"shared session" is a single-slot mailbox, not a log.

### C2. `lib/webui.py:436` — `_api_overseer()` returns early; nested-schema builder is dead code
```python
return {**bundle, **overlay}
queue = _read_json(...)   # unreachable
...
overseer_card = {...}     # unreachable
```
`bundle` is `state_format.format_dashboard()` which returns **flat** keys, but
the frontend `makeCards(j)` consumes **nested** `j.overseer`, `j.daemon`,
`j.vram`, `j.schedule`, `j.queue`, `j.processes`. None exist in the live payload,
so the overseer pane renders Big/Tiny/Proxy/Overseer all "stopped", 0 sessions,
GPU "—", empty queue/schedule/processes. The dead code also references undefined
names (`ov_state`, `minify`, `steps_state`, `proxy`) and would `NameError` if the
`return` were removed.

## 🟠 HIGH

### H1. `lib/webui.py:1068,1162` + template — TUI↔webui bridge is one-way dead
The template has **no `EventSource`, no `/webui-events`, no `/webui-send`**. The
chat is driven entirely by `POST /api/chat` NDJSON + `localStorage`. TUI writes
responses to the bridge → nothing reads them. `/webui-send` and `/webui-events`
are dead endpoints.

### H2. `lib/webui.py:626–659` — `_handle_webui_send` writes to bridge AND runs `claude -p`
If the TUI is running, the same message is answered twice (TUI via bridge, webui
via its own claude call). Moot only because the frontend never calls
`/webui-send`.

### H3. `lib/grammar_proxy.py:654-665` — chunked requests bypass grammar stripping when minify is off
The proxy's core job is stripping the `grammar` field llama-server can't parse.
But the chunked path only strips when minify is fully enabled; `_forward_raw`
forwards headers+body verbatim. With `CORTEXAGENT_MINIFY=off`, slimtoken
unavailable, or `CORTEXAGENT_MINIFY_CHUNKED=off`, chunked requests (the common
Claude Code transport) pass `grammar` straight to llama-server → 400. The
non-chunked path strips grammar unconditionally — the gap is chunked-only.

### H4. `lib/statusline.py:84` vs `lib/config.py:328` — hardcoded `daemon.sock` but daemon binds `control.sock`
The statusline VRAM breakdown silently returns `""` — feature is broken.
README.md:16 repeats the wrong `daemon.sock`.

- **M12. `lib/overseer.py:468-488`** — copy-paste of `_check_session_health` body

## Shared-session reality (unified-session gap)

Today the webui + TUI + overseer do **NOT** share one session, and the overseer
does not appear in any chat:

- **Webui ↔ CLI/proxy:** webui sends `X-CortexAgent-Session: <daemon session pid>`
  to the proxy, so *if* a CLI session is active the webui nominally shares the
  proxy's session context. But the webui resends the full message history on
  every request, and the TUI runs `claude -p` directly rather than through the
  proxy.
- **Webui ↔ TUI:** the only link is the session bridge file, which (a) is
  destroyed on every write (C1), (b) is never read by the frontend (H1), and
  (c) is only written for responses nobody consumes.
- **Overseer:** zero references to the session bridge; it never emits chat
  messages. It is a background scheduler that writes state JSON files.
- **Usernames:** the frontend hardcodes `ava = role === 'user' ? 'You' : '🧠'`;
  there is no username/display-name field anywhere in the bridge schema, and no
  "overseer" vs "big model" identity.

**What's missing for a true multi-agent chat (overseer + big model under
different usernames):**
1. Fix `SessionBridge.write()` to genuinely append (open `"a"` with `flock`, or
   read-modify-write under a lock).
2. Add a `username`/`display_name` field to bridge events and render it in the
   frontend (e.g. `You` / `Big Model` / `Overseer`).
3. Make the frontend consume the bridge (real `EventSource` to `/webui-events`,
   or fold bridge events into the `/api/chat` stream).
4. Route the TUI through the same grammar-proxy session the webui uses (or make
   the bridge the single source of truth for both).
5. Have the overseer emit chat events to the bridge (origin `overseer`) for its
   scheduled-task activity, and have the webui/TUI render them under the overseer
   username.
6. Fix `_api_overseer` (C2) so the pane's nested schema is actually served.
